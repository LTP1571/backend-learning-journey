Toàn bộ nội dung buổi 8/8: framework sinh ra để làm gì, Initializr tạo ra cái gì, project gồm những phần nào, và app chạy theo trình tự nào khi khởi động.

01

Framework và library

Trước khi biết Spring Boot làm gì, phải biết nó thay bạn làm phần nào.

Sinh ra để giải quyết chuyện gì: để tự làm một server bằng Java thuần, bạn phải mở socket lắng nghe port, đọc từng dòng văn bản thô của HTTP request, tự tách method / URL / header / body, tự chuyển JSON thành object, tự mở và đóng kết nối database. Hàng nghìn dòng, và chưa dòng nào liên quan tới việc quản lý todo. Khối đó lặp y hệt ở mọi dự án, nên người ta đóng gói sẵn.

Spring Boot là framework. Bạn không viết vòng điều phối, bạn chỉ đánh dấu class rồi để nó gọi tới.

02

Spring Initializr

Địa chỉ start.spring.io. Không phải một phần của Spring Boot, không nằm trong project, không chạy cùng ứng dụng. Chỉ là máy sinh khung project, dùng đúng một lần.

Nó sinh ra đúng ba thứ

  • Một pom.xml đã điền sẵn tên project, phiên bản Java và danh sách dependency.
  • Cây thư mục rỗng đúng chuẩn Maven.
  • Một class khởi động có hàm main.

Hết. Nó không sinh Controller, Service, Entity, không viết hộ dòng logic nào.

Giá trị thật của nó không phải tạo thư mục — việc đó gõ tay được. Giá trị nằm ở chỗ nó tra bảng tương thích giúp bạn: mỗi dependency phải khai đúng tên nhóm, tên gói và phiên bản khớp nhau, sai một chữ là project không build.

03

Cấu trúc project

Bốn phần cần nắm. Phần còn lại chưa đụng tới ở Nấc 1.

todo/
├── pom.xml              ← khai báo dependency, phiên bản Java
├── src/main/java/
│   └── com/ltp/todo/
│       └── TodoApplication.java   ← điểm khởi động, chứa main
├── src/main/resources/
│   └── application.properties     ← cấu hình DB, port
└── src/test/java/       ← chưa dùng ở Nấc 1

pom.xml

Bản khai báo của Maven: project tên gì, dùng Java mấy, cần thư viện nào. Maven đọc file này rồi tự tải thư viện về. Sửa nó khi cần thêm hoặc bớt dependency.

src/main/java

Toàn bộ code bạn viết nằm ở đây, và phải nằm trong package.

application.properties

Không phải code, chỉ là các cặp khóa và giá trị. Đây là nơi khai địa chỉ database, user, mật khẩu, port.

src/test/java

Chỗ viết test. Nấc 1 chưa động tới.

04

Package và annotation

Hai thứ quyết định Spring có nhìn thấy code của bạn hay không.

Package

Package chính là thư mục lồng nhau, tên package phải khớp đúng đường dẫn: com.ltp.todo nghĩa là com/ltp/todo.

Ở PRO192, package chỉ để sắp xếp cho gọn. Trong Spring Boot nó có vai trò khác hẳn: vị trí package quyết định class của bạn có được nạp hay không, vì phạm vi quét lấy vị trí file khởi động làm gốc.

Annotation

Một cái nhãn dán lên class, method hoặc field, viết bằng ký tự @ cộng một cái tên. Bạn đã gặp @Override ở PRO192.

Nhãn tự nó không làm gì cả. Nó chỉ có tác dụng khi có một bên khác đọc nó:

  • @Override — bên đọc là trình biên dịch, kiểm tra xem method có thật sự ghi đè không.
  • Annotation của Spring — bên đọc là Spring, lúc khởi động. Thấy nhãn thì tạo bean, không thấy thì bỏ qua.

Ví dụ đời thường: dán nhãn "dễ vỡ" lên thùng hàng. Nhãn không làm thùng cứng hơn — nó chỉ có ích khi người bốc vác nhìn thấy và xử lý khác đi.

05

Bean và ApplicationContext

Chỗ Spring Boot khác hẳn cách bạn quen ở PRO192.

Bean là một object do Spring tạo ra và giữ hộ bạn, thay vì bạn tự tạo bằng new. Bạn chỉ đánh dấu class bằng annotation; Spring tự tạo object lúc khởi động, cất vào một kho chung, rồi khi class khác cần thì tự đưa tới. Kho chung đó tên là ApplicationContext.

Vì sao không tự new

Nếu Service tự new Repository loại PostgreSQL
  • Không test được Service nếu chưa bật database thật.
  • Đổi sang MySQL phải mở Service ra sửa, dù Service chẳng làm gì với database.
Nếu để Spring cấp phát
  • Đổi sang MySQL: thay bean trong kho, không đụng chữ nào trong Service.
  • Muốn test: đưa cho nó một Repository giả chạy trong bộ nhớ.
Ý cốt lõi: Service phụ thuộc vào vai trò "một Repository", chứ không phụ thuộc vào một class cụ thể nào. Ai lấp vào vai trò đó là quyết định nằm ngoài Service. Đây là lý do Repository được khai báo dưới dạng interface — interface chính là cách Java mô tả một vai trò.
06

Ba tầng Controller, Service, Repository

Quy ước tổ chức code, không phải cú pháp bắt buộc. Initializr không sinh sẵn — bạn tự tạo package từ 9/8.

Sinh ra để giải quyết chuyện gì: một request "thêm todo" phải làm ba việc khác loại nhau — hiểu client muốn gì, quyết định đúng sai theo quy tắc, và ghi xuống database. Nhét cả ba vào một class thì khi đổi database, bạn phải sửa cả phần đang xử lý HTTP, dù hai thứ không liên quan gì nhau.
Controller

Nhận HTTP request, trả response kèm status code. Không chứa logic nghiệp vụ.

Service

Logic nghiệp vụ: kiểm tra hợp lệ, quyết định, xử lý.

Repository

Đọc và ghi database.

Hai quy tắc phải thuộc

  • Luồng một chiều, không nhảy tầng. Client → Controller → Service → Repository → Database. Controller không gọi thẳng Repository.
  • Response đi ngược lại đúng đường đó. Repository trả dữ liệu cho Service, Service trả cho Controller, Controller mới đóng gói thành JSON kèm status code.
Nối lại với câu 404 của tuần 1: Repository là nơi phát hiện ID không tồn tại, Service là nơi báo động bằng cách ném exception, còn nơi quyết định đổi exception đó thành mã 404 là tầng web — cụ thể là exception handler (bạn sẽ tự viết ngày 13/8), vì chỉ tầng đó biết đến khái niệm HTTP. Controller không viết dòng nào về 404 cả.

08

Đọc log lỗi

Kỹ năng dùng mỗi ngày từ giờ trở đi.

Cấu trúc một dòng log

Sáu phần theo thứ tự: thời gian → mức độ → PID → tên app và tên thread → class ghi ra dòng này → nội dung.

Mức độ là phần quét mắt đầu tiên: INFO bình thường, WARN bất thường nhưng chạy tiếp được, ERROR hỏng.

Quy tắc quan trọng nhất: đọc ngược từ dưới lên. Khối cuối cùng có khung sao là bản tóm tắt do Spring Boot tự phân tích và viết ra cho người đọc. Khối stack trace dài ngoằng phía trên là truy vết kỹ thuật — người mới hay lao vào đọc trước rồi hoảng.

Khối tóm tắt có ba mục

Description: ← hậu quả: cái gì đã hỏng
Failed to configure a DataSource: 'url' attribute is not specified...

Reason: ← nguyên nhân: thứ bạn phải xử lý
Failed to determine a suitable driver class

Action: ← gợi ý, chỉ tham khảo
Consider the following: ...
Đọc Reason trước, Description sau. Sửa nguyên nhân thì hậu quả tự hết. Spring Boot đã tách sẵn hiện tượng và nguyên nhân thành hai nhãn riêng — dùng nó để rèn thói quen phân biệt hai thứ đó.
Action đọc nhưng đừng làm theo mù quáng. Trong ca ngày 8/8, Spring gợi ý dùng database nhúng H2 — gợi ý viết chung cho mọi người, không biết bạn đã có PostgreSQL. Log gợi ý gì thì cứ đọc, quyết định vẫn là của bạn.

Nguyên nhân thật

Có Spring Data JPA nên lúc khởi động Spring cố dựng sẵn một connection pool — kho kết nối tới database, dùng lại nhiều lần thay vì mở đóng liên tục. Để dựng kho, nó cần biết nối tới đâu: địa chỉ, cổng, tên database, user, mật khẩu. Những thứ đó chưa được khai. Không có địa chỉ thì cũng không suy ra được nên dùng driver nào.

Spring chọn dừng hẳn thay vì chạy tiếp với một nửa cấu hình hỏng, vì chạy tiếp thì lỗi sẽ nổ ra lúc có request thật, khó truy hơn nhiều.

Bốn câu của ngày 8/8

  1. Khác nhau cốt lõi giữa library và framework là gì? Hỏi: ai giữ quyền gọi ai.
  2. Vì sao cần cả Spring Data JPA lẫn PostgreSQL Driver? Chỉ một trong hai có được không? Hỏi: thiếu một cái thì khâu nào trong chuỗi bị đứt.
  3. Bạn tạo class mới ở package com.ltp.utils, còn file khởi động ở com.ltp.todo. Spring có nhận class đó không, vì sao? Xem lại bước 3 của trình tự khởi động, chú ý chữ "package con".
  4. Vì sao app khởi động rồi tắt ngay? Trả lời theo cơ chế, đừng mô tả lại hiện tượng. Xem bước 4 và 5, cộng với dòng Reason trong log.

Nhắc lại cách trả lời câu "vì sao": gạch bỏ mọi từ đã có trong đề bài. Nếu không còn gì thì đang mô tả, chưa nêu nguyên nhân.
