01

Client và server

Sinh ra để giải quyết chuyện gì: hai máy tính ở hai nơi khác nhau, không dùng chung bộ nhớ, không nhìn thấy nhau. Cách duy nhất để trao đổi dữ liệu là gửi cho nhau những gói tin có định dạng thống nhất. HTTP là bộ quy ước về định dạng đó.

Client

Bên mở lời trước. Postman, trình duyệt, app điện thoại. Tạo request, gửi đi, chờ, hiển thị kết quả.

Server

Bên luôn trực máy, chỉ trả lời. Không bao giờ tự gọi cho client trong HTTP. Nhận request, xử lý, trả response.

Vòng đời một request

Client đóng góimethod, endpoint, header, body. Chưa có gì rời khỏi máy.
Gửi qua mạngDựa vào địa chỉ và port trong URL, không phải endpoint.
Server xử lýĐọc method + endpoint, đọc/ghi database.
Server tạo responseStatus code + body (nếu có).
Client hiển thịPostman in ra status code và body.
Stateless. Xong bước 5, kết nối đóng lại. Server không nhớ bạn vừa hỏi gì. Request tiếp theo là một câu chuyện hoàn toàn mới. Đây là lý do sau này phải có token hoặc session — để tự nhắc server biết bạn là ai.
02

Địa chỉ: localhost và port

localhost:8080 không phải một thứ, mà là hai thứ trả lời hai câu hỏi khác nhau.

localhost — máy nào?

Tên gọi của "chính máy đang chạy lệnh này", tương ứng IP 127.0.0.1. Request không ra Internet, nó quay đầu về máy bạn. Nhờ vậy bạn test được server ngay mà không cần thuê máy chủ.

8080 — cửa nào trên máy đó?

Một máy chạy nhiều chương trình cùng nghe mạng. IP dẫn tới đúng toà nhà, port là số phòng. Server của bạn ở :8080, PostgreSQL ở :5432 — cùng máy, khác phòng.

Phân biệt hai loại hỏng. Gõ nhầm port → connection refused, không có status code nào cả, vì request chưa tới được server. Còn 4xx/5xx chỉ tồn tại khi request đã tới server và server đã trả lời. Nhầm hai thứ này là nhầm chỗ đi tìm lỗi.
03

HTTP method

Sinh ra để giải quyết chuyện gì: endpoint trả lời "tác động lên cái gì", method trả lời "làm gì với nó". Hai thông tin độc lập, không suy ra được từ nhau. Nhìn /todos/7, server không thể biết bạn muốn xem, sửa hay xoá — mà server không được phép đoán.

04

REST API và CRUD

Sinh ra để giải quyết chuyện gì: nếu mỗi hành động đẻ ra một endpoint riêng (/getTodo, /deleteTodo, /updateTodo…) thì API phình ra vô tận và không ai đoán được tên. REST đặt ra quy ước: endpoint là danh từ số nhiều, hành động nằm ở method. Nhờ vậy chỉ cần hai endpoint là đủ cho toàn bộ vòng đời một tài nguyên.

Ba quy tắc đặt endpoint

Danh từ, không động từ

/todos đúng. /createNewTodo sai — động từ đã nằm ở method rồi, viết lại là thừa.

Số nhiều

/todos là cả bộ sưu tập, /todos/7 là một phần tử trong đó. Đọc như đường dẫn thư mục.

Phân cấp theo sở hữu

/users/3/todos = các todo của user 3. Cấp sau thuộc về cấp trước.

05

Status code

Con số ba chữ số để client biết chuyện gì đã xảy ra mà không cần đọc body. Chữ số đầu tiên là nhóm, và nhóm mới là thứ phải thuộc.

2xxThành công

Server đã làm đúng điều được yêu cầu.

4xxLỗi phía client

Request có vấn đề. Server vẫn khoẻ. Client gửi lại y hệt vẫn hỏng.

5xxLỗi phía server

Request hợp lệ nhưng server tự gãy. Client gửi lại y hệt có thể chạy được.

Ranh giới 4xx / 5xx: sửa được ở phía nào?
4xx — client sửa thì hếtSửa lại URL, điền đủ field, đăng nhập lại, hỏi đúng id có thật. Server không phải làm gì.
5xx — client không sửa được gìDatabase tắt, code ném exception, hết bộ nhớ. Người phải sửa là bạn, trong code server.

Bẫy quen thuộc: hỏi GET /todos/999 mà không có bản ghi nào id 999 → đây là 404, không phải 500. Server hoàn toàn khoẻ mạnh và đã trả lời chính xác: thứ bạn hỏi không tồn tại. Chỉ khi code của server tự gãy trong lúc xử lý thì mới là 5xx.

CodeTênDùng khi

401 và 403 hay bị đảo. Mẹo nhớ: 401 là "anh là ai?", 403 là "biết anh rồi, nhưng không được".

06

Database cơ bản

Sinh ra để giải quyết chuyện gì: biến trong RAM chết theo tiến trình — tắt server là mất sạch. Database giữ dữ liệu lại sau khi chương trình tắt, và cho nhiều người cùng đọc/ghi mà không giẫm lên nhau.
idtitleis_donecreated_at
1Cấu hình Gittrue2026-08-01
7Học git flowfalse2026-08-04
8Ôn lại HTTPfalse2026-08-05
table — cả bảng todos này row — một todo cụ thể, ví dụ id 7 column — một thuộc tính, ví dụ is_done

Primary key

Cột định danh duy nhất một row trong bảng, không trùng, không rỗng. Ở đây là id. Không có nó thì GET /todos/7 gãy đầu tiên — vì server không còn cách nào chỉ đúng một dòng để lấy về hoặc để xoá.

Foreign key

Cột trong bảng này trỏ tới primary key của bảng khác. Một user có nhiều todo, nên user_id nằm ở bảng todos — bên "nhiều" giữ khoá. Nếu để ở bảng users thì một ô phải chứa nhiều id, mà một ô chỉ chứa được một giá trị.

Cùng một dữ liệu, ba hình dạng

row trong database
id       7
title    Học git flow
is_done  false
object trong Java
Todo với 3 field
+ getter/setter
+ kiểu dữ liệu Java
json gửi cho client
{ "id": 7,
  "title": "Học git flow",
  "isDone": false }

Giống nhau: cùng một sự thật, cùng bộ thuộc tính. Khác nhau: row nằm trên đĩa và do PostgreSQL quản lý; object nằm trong RAM, có hành vi (method), chết khi tiến trình tắt; JSON là chuỗi ký tự thuần, không có hành vi, chỉ để đi trên mạng. Toàn bộ công việc backend phần lớn là dịch qua lại giữa ba tầng này.
